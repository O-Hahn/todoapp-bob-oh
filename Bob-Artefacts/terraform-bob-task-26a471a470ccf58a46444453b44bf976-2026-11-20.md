> 🔧 **write_file** — # Terraform: IBM Cloud services for the ToDo app

Provisions the IBM Cloud services the app depends on:

- **IBM Cloudant** instance plus a `Manager` IAM service key. The server creates its databases and indexes at startup (`CloudantAppRepository.init`), so Terraform does not create them.
- **IBM watsonx Orchestrate** instance. The agent, toolkit and connection are imported afterwards with [`orchestrate/deploy.sh`](../orchestrate/deploy.sh).

Region, plans and names are variables with no defaults. You supply them in `terraform.tfvars`.

## Prerequisites

- Terraform >= 1.5.0
- An existing IBM Cloud resource group
- An IBM Cloud API key with permission to create Cloudant and watsonx Orchestrate instances, exported in your shell (never stored in files):

```bash
export IC_API_KEY="<your-ibm-cloud-api-key>"
```

## Usage

```bash
cd terraform
cp terraform.tfvars.example terraform.tfvars   # edit values; file is git-ignored
terraform init
terraform plan
terraform apply
```

## Wire the outputs into the app

Cloudant values are sensitive. Read them and place them in `.env.openshift` (git-ignored):

```bash
terraform output -raw cloudant_url      # -> CLOUDANT_URL
terraform output -raw cloudant_apikey   # -> CLOUDANT_APIKEY
```

Remove `CLOUDANT_USERNAME` and `CLOUDANT_PASSWORD` from `.env.openshift` when using the API key. Then run `make deploy-dev` from the repository root.

For watsonx Orchestrate:

```bash
orchestrate env add -n my-saas -u "$(terraform output -raw orchestrate_api_url)"
orchestrate env activate my-saas --api-key "$IC_API_KEY"
```

Then follow [`orchestrate/README.md`](../orchestrate/README.md).

## State

Terraform state contains the service key secrets. State and `terraform.tfvars` are git-ignored. Use a protected remote backend if you share this configuration with others.

## Destroy

```bash
terraform destroy
```

### 🤖 Assistant

I added a Terraform configuration in [`terraform/`](terraform/README.md) that provisions Cloudant and watsonx Orchestrate on IBM Cloud. `terraform fmt -check` and `terraform validate` pass, but I haven't run `plan` or `apply`. Those need your `IC_API_KEY` and a `terraform.tfvars` file.

What it creates:
- **Cloudant:** an instance plus a `Manager` IAM service key. The app already creates its own databases and indexes at startup, and that needs `Manager`.
- **watsonx Orchestrate:** an instance only. The agent, toolkit and connection are still imported with [`orchestrate/deploy.sh`](orchestrate/deploy.sh).
- **Resource group:** an existing one, looked up by name.
- **Variables:** region, plans and names have no defaults. Copy [`terraform.tfvars.example`](terraform/terraform.tfvars.example) to `terraform.tfvars` and fill them in.

Outputs:
- **Sensitive:** `cloudant_url` and `cloudant_apikey`. Copy them into `.env.openshift` as `CLOUDANT_URL` and `CLOUDANT_APIKEY`.
- **Plain:** `cloudant_crn`, `orchestrate_guid`, `orchestrate_crn` and `orchestrate_api_url`. The last one is what you pass to `orchestrate env add -u`.

The provider is pinned to `~> 2.10` (2.10.0 was the latest stable when I checked). Plan names were not validated against your account. I took the `watsonx-orchestrate` service name and the plan values `lite`, `essentials-agentic-mau` and `standard-agentic-mau` from the IBM Terraform module's docs.

I also made these changes:
- Added Terraform state, `.terraform/` and `tfvars` patterns to `.gitignore`.
- Added a pointer to the Terraform README in the main `README.md`.

- Running `terraform init` created `terraform/.terraform.lock.hcl`, which I left uncommitted so you can add it to version control.
